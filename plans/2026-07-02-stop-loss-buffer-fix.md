# 動能/反轉策略止損無緩衝修正（ranker.py DD-15）

> 狀態：已執行完成，對應分支 `fix/stop-loss-buffer`

## Context

使用者在檢視報告時觀察到一個現象：止損價常常等於買入區間下緣，覺得不合理。

追查後用 `data/watchlist.json` 的實際數據驗證：

| 股票 | 買入區間 | 止損 | 有無緩衝 |
|------|---------|------|---------|
| KLAC（較早） | $295～$302 | $285 | 有，低於下緣約 3.4% |
| AMAT（較早） | $710～$723 | $690 | 有，低於下緣約 2.8% |
| CB／KHC／V／AJG／LIN（近期） | 各自區間 | 等於下緣 | **無，完全相等** |

根因在 `src/ranker.py` 的 `SYSTEM_PROMPT`：動能策略的買入區間下緣本身就是 EMA20（DD-12），但止損規則只寫
「跌破 EMA20」，只有方向詞沒有明確百分比緩衝。AI 有時會照字面把止損直接設成等於 EMA20——剛好等於買入區間
下緣，等於一買進去就已經觸發止損，沒有容錯空間。對照突破策略已經有「跌回 High_20D 下方 2%」的明確緩衝，
唯獨動能策略缺這個緩衝。較早的 KLAC/AMAT 有自然緩衝只是巧合（AI 自行加了緩衝），不是規則保證的，證明這
是 Prompt 措辭模糊導致 AI 解讀不一致，不是必然發生的問題。

使用者接著要求一併檢查反轉策略是否有同樣問題。分析結論：反轉策略的買入區間錨點是 EMA50、止損錨點是
Low_20D，兩者是不同技術價位，正常情況下深跌後 Low_20D 本來就明顯低於 EMA50，天生有緩衝，風險比動能策略
低很多。但反轉策略買入區間規則 2「`buy_zone` 下緣不得低於 `Low_20D`」這個地板條件被觸發時（EMA50 已經
貼近或低於 Low_20D，屬於長期陰跌而非急殺反彈的少見情況），buy_zone 下緣可能被拉高卡在 Low_20D，此時若
AI 把「止損：Low_20D 下方」照字面解讀成等於 Low_20D，就會重演同樣問題。目前系統還沒有真正的反轉策略歷史
紀錄可以實測驗證（近期都是 BULL_TREND，只有 PANIC_REVERSAL 才會觸發反轉策略），這是根因層面的風險，不是
已證實發生過的案例，但基於同一類措辭缺陷，一併修正。

## 執行內容

### `src/ranker.py` — `SYSTEM_PROMPT`

**動能策略**：
```diff
- 目標：+10%~20%；止損：跌破 EMA20
+ 目標：+10%~20%；止損：EMA20 下方 2%（不得設為等於買入區間下緣，須低於 EMA20）
```

**反轉策略**：
```diff
- 目標：+8%~15%；止損：Low_20D 下方（不得設在 EMA50 之上，避免止損過寬）
+ 目標：+8%~15%；止損：Low_20D 下方 2%（不得設在 EMA50 之上，避免止損過寬；不得等於買入區間下緣）
```

兩處都採用與突破策略一致的「明確百分比 + 括號補充『不得等於買入區間下緣』的顯式提醒」寫法，直接針對已
發現的失敗模式（AI 把方向詞照字面解讀成止損=錨點本身）提出反制指令，不只是加個數字了事。

### 為何是純 Prompt 修正，不動 tracker.py

探索確認 `tracker.py` 的 `_parse_stop_loss()`／`_parse_buy_zone()` 只解析 `"$X"`／`"$X~$Y"` 字串格式，
`_eval_status()` 也沒有任何「`stop_loss` 必須小於 `buy_zone` 下緣」的斷言或假設，純粹把兩個獨立欄位存起
來比較。所以這個修正完全不會因為改了 Prompt 字面而在 tracker.py 端出現新的邊界情況，也不需要動 JSON
schema，是零程式碼影響的純文字修正。

### 考慮過的方案

**選項 A（採用）**：Prompt 文字加上明確百分比緩衝 + 顯式反制提醒。

**選項 B（捨棄）**：在 Python 端強制修正 AI 回傳的 `stop_loss`（例如收到後自動下修 2%）。
捨棄原因：偏離「AI 給出完整交易計畫」的既有架構精神（DD-12 已經在這點上做過取捨，`buy_zone` 也是完全由
AI 自行輸出，不做 Python 端確定性計算），且會讓 AI 給出的 `strategy_reason`／`risk` 裡描述的止損邏輯，
跟實際存入 `watchlist.json` 的止損價不一致（AI 說「跌破 EMA20 止損」，但實際存的是 EMA20 的 98%），
治標不治本，且會讓除錯更困難（不知道是 AI 給錯還是程式改過）。
