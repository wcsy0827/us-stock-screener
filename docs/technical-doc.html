00 · Pipeline

系統總覽

每個交易日執行一次，從 S&P 500 全市場（~503 支）出發，經過三層漏斗式篩選，最終由 AI 挑出至多 3 支個股並附完整交易計畫，再由狀態機追蹤是否進場、何時出場。全流程按下表順序串接，Regime（大盤環境）判定被刻意插在 L2 之前，因為 L2 的分數門檻要依當日環境動態調整。

Step模組做什麼輸出

01 · filter.py

L1 硬篩選

分兩段執行：先做流動性硬篩，通過後才查財報防禦牆（財報查詢有 API 成本，晚一點做可以省流量）。

第一段：流動性 + 波動率上限

條件門檻備註
股價> $5
30 日平均日成交額> $1,000 萬MIN_DOLLAR_VOLUME，avg_vol_30 × close
市值> $3 億MIN_MARKET_CAP；None 視同不足，直接排除
近期成交近 5 日有成交排除停牌股
ATR%≤ 8%MAX_ATR_PCT；ATR14÷收盤價；歷史<15筆不排除
filter.py DD-8

ATR% 上限是後補的風控層——三策略的止損後來統一收斂成「錨點下方 2%」固定緩衝（見 §04 L3 策略邏輯），但緩衝寬度沒有對照個股自身波動。日均 ATR% 達 6~8% 以上時，2% 止損緩衝形同虛設，正常雜訊就足以掃損。所以在 L1 就把這類個股攔下，而不是讓它們進 L2/L3 後才在止損邏輯裡出問題。

第二段：財報防禦牆

未來 EARNINGS_BLACKOUT_DAYS = 5 個自然日內有已知財報者排除，判斷基準日是 market_date（非系統時鐘）。財報日期資訊透過三層快取取得（earnings_registry.json，TTL 30 天）：Tier 1 命中本地快取 → Tier 2 讀 yfinance info.earningsDate → Tier 3 用 ticker.calendar 精準補抓（僅對通過流動性篩選後的股票觸發，控制 I/O 成本）。查無資料一律視為「無已知財報」放行，而非阻擋。

為何是 5 天而非 3 天：機構通常財報前 3~5 天就開始調倉，隱含波動率提前上升、期權溢價膨脹；3 天窗口仍可能在 IV 高點進場。
02 · market.py

Regime 大盤感知

用「市場廣度」（S&P 500 中收盤價站上 50 日均線的比例，3 日平滑）與「VIX」兩個變數，把每個交易日分類成五種環境象限，決定 L2 門檻鬆緊與 L3 的主推策略。

依 market.py::determine_market_regime() 實際程式邏輯繪製（非僅規格表格）。虛實分界線：廣度 35% / 60%，VIX 20（中段分界）/ 25（低廣度分界）。

邊界抖動防護

  • 3 日廣度平滑：每日廣度用近 3 個交易日的算術平均，避免單日雜訊造成 Regime 每天翻轉。
  • 遲滯帶（Hysteresis，±2%）：廣度落在 35% 或 60% 邊界 ±2% 範圍內時，沿用前一日 Regime；但若 VIX 跨越了「高VIX組（PANIC/CONSOLIDATION_VOLATILE）↔ 低VIX組」的結構邊界，則不套用遲滯、強制重新計算。讀取 last_run.json 的前一日 regime/market_date 實作，需嚴格校驗前一日日期早於當日才生效（防同日重跑污染）。

VIX 下載失敗保護

失敗時使用預設值 20.0（正常波動中間值，讓判定退化為由廣度主導），同時回傳 vix_ok=False，pipeline 會在 L3 之前中斷、不呼叫 DeepSeek。

03 · scorer.py

L2 技術評分

對通過 L1 的個股做 100 分制純技術評分，六個維度，各自獨立設計理由：

維度滿分邏輯摘要

RSI 健康區間1850~70 滿分；40~50 或 70~80 半分；BULL_TREND 下 50~80 滿分、>80 半分（DD-6）
MACD 柱狀體17正且遞增滿分；正但遞減半分；負值 0 分
量能（含趨勢）15VTF 基礎分 × 5日量能趨勢係數；K_pos<0.6（爆量卻收在低檔）時整項歸零（出貨阻斷，DD-4/7）
多週期動能1520日 ATR 倍數動能 × 5日方向確認，防止「中期強但短線已反轉」誤判（DD-5/8）
相對強度 RS15個股5日報酬 − 板塊ETF 5日報酬；≥+2%滿分15，<-0.5%得0分（DD-9）

RSI>80 是軟過濾：該項得0分（或BULL下半分）但不逐出候選池——PANIC_REVERSAL環境下超強勢股可能是唯一抗跌標的，硬排除會在最需要它的環境把它排掉（DD-1）。

固定分數門檻的通過家數完全跟著大盤強弱擺動（強勢盤可能破200支，弱勢盤不到20支），無法穩定收斂。解法：品質門檻篩完後，若 > L2_TARGET_COUNT(55) 支，取第55名分數當 cutoff，只留 ≥cutoff 者（同分邊界都留，不加 tie-breaker）；強制放行股不受此上限排除；本來就 <55 支時不硬湊數量。

04 · ranker.py

L3 AI 精選

把 L2 候選（最多送 MAX_CANDIDATES_TO_AI=40 支給AI，每產業上限 MAX_SECTOR_CANDIDATES=8 支防止單一板塊霸榜）透過結構化 XML Prompt 交給 DeepSeek，AI 輸出至多 3 支個股的完整交易計畫（買入區間、止損、目標、持有期、策略、理由）。BEAR_DISTRIBUTION 環境直接回傳空清單，不呼叫 API。

候選池表格關鍵欄位（節選）

完整表格共 30 欄，除 Ticker/L2_Score/RSI 等基礎欄外，關鍵是把過去只存在於 Python 內部判斷、AI 看不到的指標「曝露」出來——這是 DD-12/13/19 反覆修正的核心問題：Prompt 文字要求 AI 判斷某個指標，但表格裡根本沒給那個數字。

欄位用途

High_20D, Low_20D突破策略壓力位／反轉策略左側支撐

ranker.py DD-19 · 為何動能策略改成 ATR 錨定淺回檔

舊版（DD-12）要求動能股回檔到 EMA20~EMA10（現價下方4~8%）才進場——但L2的職責就是挑「均線多頭、還沒回檔」的最強勢股，越強的股票越等不到這麼深的回檔，5日 watch 窗口內常常等不到就到期。實測 2026-07-06 報告 13支追蹤股中 4 支死於「已追高，錯過買點」。改成 ATR 錨定的淺回檔帶後，區間深度隨個股自身波動自動調整。

其他 Prompt 機制

  • 產業ETF背景：同時顯示5日與20日漲跌，讓AI判斷短中線方向是否一致。
  • 歷史績效回饋（DD-16）：非空時在Prompt末尾附加第四區塊，注入 ai_hints.json 的敘述性統計（見§07），並固定附「樣本有限、不得覆蓋Regime策略方向」警語。
  • PANIC_REVERSAL低分豁免：反轉股L2分數天生偏低是正常現象，AI須忽略低分偏見，專注審查Momentum_ATR是否拋壓衰竭。
  • 財報極端風控：禁止選 Earnings_Days_Left≤3 的個股（filter.py財報牆是第一道，此為AI側雙重保護）。
05 · tracker.py

Tracker 進出場狀態機

L3 選出的股票不會立刻視為「已進場」——先進 watch，次一交易日盤中觸價才轉 active（1-day lag），最終四態結算並歸檔至 performance_history.json。

watch
→
active
→
settled
（4態）

旁支：watch → invalid（失效）、watch/invalid → expired（到期）。active 一旦成立，只由結算邏輯決定何時離開——不會被到期規則、也不會被均線/止損跌破判斷提前踢出（DD-6/17，見下方說明）。

進場：盤中限價單模擬（DD-19）

使用者真實下單方式是在買入區間上緣掛限價單。所以判斷「是否已觸價」用當日最低價而非收盤價：today_low ≤ buy_zone_upper 就視為成交，此檢查優先於下方所有收盤價判定（含反轉止損、動能EMA20失效、追高失效）。若同日觸價又跌破止損（跳空急殺），不再拒絕進場，而是視為當日已成交、交由結算邏輯立即判 CLOSED_LOSS（保留真實虧損紀錄，而非讓它憑空消失）。進場代理價 = buy_zone_upper（使用者實際掛單價，取代舊版的「收盤價」）。

結算優先序（每日依序判定，盤中High/Low優先於收盤）

  1. 黑天鵝防禦：today_low≤effective_stop_loss 且 today_high≥target 同時成立 → 保守判 CLOSED_LOSS
  2. 盤中止損：today_low ≤ effective_stop_loss → CLOSED_LOSS（出場價=止損絕對值）
  3. 盤中停利：today_high ≥ target → CLOSED_PROFIT（出場價=目標絕對值）
  4. 移動停利：峰值浮盈>10% 且收盤回撤≥5%（僅動能/突破策略，反轉策略排除）→ CLOSED_TRAILING_STOP（出場價=收盤）
  5. 持倉到期：active_days ≥ hold_period（AI給的持有天數解析值，下界1）→ FORCE_EXPIRED（出場價=收盤）

風控雙欄位：計畫止損 vs 動態止損

planned_stop_loss（AI原始值，唯讀，只作拆股縮放基底）與 effective_stop_loss（實際生效值）分離。進場後收盤達到「距目標50%」時，effective_stop_loss 自動上移至 buy_zone_upper（保本鎖定，is_breakeven_locked=true，僅觸發一次）。這兩個欄位存在的理由是：若只有單一欄位，拆股縮放與保本上移會互相污染，難以回推正確基準。

失效判定：反轉股用絕對止損，動能/突破用EMA20——但僅適用 watch 狀態

watch 狀態下：反轉策略 price<stop_loss → invalid；其餘策略 price<EMA20 → invalid。但這套判斷只適用 watch，不適用 active。DD-17 移除了「active 部位被 _eval_status() 判定失效」的路徑——原因是舊邏輯會讓虧損部位在被判 invalid 後跳過結算，永遠不會寫入 performance_history.json，勝率統計因此系統性偏高。active 部位的生死完全交給上面的四態結算。

拆股免疫

yfinance 的 auto_adjust=True 會在拆股後回溯修改全部歷史收盤價，若不處理，watchlist 記錄的絕對止損價會變成「幽靈訊號」。做法：訊號建立當下即時記錄 signal_date_close，每次評估計算 split_factor，在記憶體中臨時縮放全部風控欄位（不寫回 watchlist，避免累積誤差）。

06 · tracker.py DD-20

組合層級持倉上限：事前掛單名單制

watchlist 原本沒有組合層上限——每日L3流入≤3支 × ATR淺回檔帶帶來的高觸價率 × 常見15交易日持有期，穩態推算約可累積 45 支同時持倉，與真實資金操作完全脫節。MAX_ACTIVE_POSITIONS（預設 5）解決這個問題。

運作方式

  • free_slots = max(0, MAX_ACTIVE_POSITIONS − 現有active數)
  • 全部 watch 條目依 優先序排序：-ai_confidence → -l2_score → symbol（缺值視為0）
  • 前 free_slots 名 = eligible（今晚報告顯示「✅建議掛單」）
  • 名單外觸價一律被擋：即使股票今天觸價，只要不在名單內就不會轉 active——因為使用者根本沒掛那張單（v2 修訂，取代「事後擇優」的v1設計）
  • 被擋條目改用收盤價重新判定：收盤已失效（跌破止損/已追高）→ 直接 invalid 清除；否則維持 watch 並標 slot_blocked_today
  • 當日結算不即時退還名額（使用者掛單當下不可能預知當天稍晚的止損）；超額持倉不強制平倉
語意對應真實操作：報告上的「✅建議掛單」= 系統認定的次日進場資格，使用者照表掛單，performance_history.json 就等於真實帳本。這是刻意的取捨——v1版「觸價者中信心高者得名額」曾被推翻，因為使用者事前只能掛前N名的單，事後才知道誰觸價會把「使用者根本沒做的交易」寫進績效資料庫。
07 · analyzer.py

Analyzer 本地績效回饋迴路

純本地統計（不連網、不呼叫API），讀 performance_history.json 已結算記錄，依 Regime × 策略 × 產業 三維度算勝率與平均報酬，寫入 ai_hints.json，L3 Prompt 末尾附加為第四區塊「歷史績效回顧」。

  • 單一分組樣本 <3 筆不產生該組提示；有效總樣本 <5 筆時完全不輸出提示（防止小樣本誤導AI）
  • 提示是描述性統計（「BULL_TREND：5筆結算，勝率60%，平均報酬+1.25%」），刻意不寫成指令式結論（不會說「禁止選能源股」）——決策主權留給Regime與候選池，回饋只供AI「權衡參考」
  • 1-cycle lag：analyzer在tracker結算之前執行，讀到的是前一輪的結算結果，當日新結算要下一輪才會反映進提示
  • 基本面關聯目前用「產業」代理——因為歷史歸檔記錄沒有存 Fwd_PE/Profit_Margin 等欄位（那些只進L3 Prompt，沒進watchlist/歸檔）

09 · 供研究使用

待研究方向（初步觀察，非結論）

以下是讀完現有邏輯後觀察到、且有具體程式碼或規格依據支撐的疑點，供你進一步用 data/performance_history.json 回測或設計實驗驗證。這些不是已抗辯確認的結論，只是研究起點的候選清單。

09-1

強勢廣度＋VIX偏高＝整批降級成保守突破，動能策略被完全捨棄

market.py:180

規格表格呈現的印象是 CONSOLIDATION_VOLATILE 只發生在廣度 35~60% 區間，但實際程式碼是 elif breadth_pct >= 35（不再檢查上限），所以廣度 ≥60%、VIX ≥20 時也會落入 CONSOLIDATION_VOLATILE，而不是 BULL_TREND——即使大盤廣度極佳，只要VIX同時偏高（例如財報季集體公布、總經數據公布日），系統當天就整批放棄動能策略，改用65分保守突破門檻。

可研究：這個隱性規則是否犧牲了「廣度好、只是短期波動上升」情境下動能策略原本能捕捉的行情，值得用歷史數據回測比較兩種分類方式的實際報酬差異。

09-2

移動停利/保本鎖定用固定百分比，未隨個股ATR%縮放

tracker.py DD-13

DD-19 已經把「進場」與「初始止損」都改成ATR錨定（因為固定EMA帶讓強勢股等不到回檔），但保本鎖定（達目標距離50%）與移動停利（峰值浮盈10%回撤5%）仍是寫死常數，對ATR%極低的防禦股與ATR%接近8%上限的成長股一視同仁。

可研究：移動停利回撤幅度是否也該用個股自身ATR%動態調整，讓高波動股不被單日雜訊提前掃出、低波動股不會停利設太鬆。

09-3

持倉上限只管「檔數」，沒有風險金額或曝險比例的概念

tracker.py DD-20

MAX_ACTIVE_POSITIONS=5 是單純的持倉檔數上限，系統沒有「每筆風險佔總資金%」或「5支同時觸發止損時的總虧損上限」設計。L1 的 MAX_ATR_PCT=8% 只限制個股波動，不代表組合層級的總風險有被控制。

可研究：是否該把持倉數量上限，換成或疊加「固定風險比例配置」（例如每筆風險固定佔總資金1%，槓桿與部位大小反推），這是機構常見的部位規模設計。

09-4

掛單優先序（AI信心→L2分數）尚未反向驗證與實際勝率的相關性

tracker.py _slot_priority_key

名額分配假設「AI信心分數愈高，未來表現愈好」，但 analyzer.py 目前只做敘述性統計回饋給AI（DD-3 明文禁止指令式結論），沒有反向檢驗「confidence 分箱後的實際勝率/報酬是否單調遞增」。這是一個可以直接用現有 performance_history.json（累積足夠樣本後）驗證的假設，不需要改任何程式碼。

可研究：把 ai_confidence 分成幾個區間（如1-5/6-7/8-10），對照各區間的實際勝率與平均報酬，確認排序鍵的有效性；若相關性弱，L2分數或許該作為主要排序鍵。

09-5

Active 持倉「訊號免疫」，即使AI隔天判斷轉弱也不會收緊止損

tracker.py DD-9

持倉中的股票若隔天又被AI選中，系統完全忽略新的 buy_zone/stop_loss/target，只延續進場當天的舊計畫——這是刻意設計（避免同一部位的績效統計被中途竄改污染）。但代價是持倉無法受益於「基本面/技術面轉差時應提前收緊止損」的動態調整。

可研究：是否該開放「單向收緊」（只允許新判斷把止損上移，不允許下移或放寬目標），在不破壞績效資料乾淨度的前提下增加風控彈性。

09-6

財報防禦牆只做排除，沒有捕捉財報後動能（PEAD）的對應策略

filter.py DD-8, earnings.md DD-E4

系統用 5 天黑名單窗口保護下行風險，但財報公布後的價格持續趨勢（post-earnings announcement drift）是有學術實證支持的異常報酬來源，目前三種策略（動能/突破/反轉）都不是針對這個現象設計的。

可研究：財報公布後首個交易日若跳空且帶量，是否值得作為第四種獨立訊號類型，與現有防禦牆並存而非衝突。

09-7

DeepSeek 單次呼叫決定當日精選，未做多次抽樣或一致性檢驗

ranker.py

每日只呼叫一次 API，若當天輸出的3支選股剛好處於AI判斷邊界（例如confidence卡在5/6分界），選股結果對Prompt措辭或當次隨機性可能較敏感，沒有機制偵測「這次判斷是否穩定」。

可研究（需權衡API成本）：對同一份候選池做2-3次獨立呼叫，比較結果是否一致；若常態性不穩定，可能代表候選池同質性太高、或Prompt指引仍有模糊地帶。

09-8

PANIC/BEAR環境下完全空手，沒有避險或降低曝險的中間選項

market.py

BEAR_DISTRIBUTION 直接回傳空選股清單，資金在確認的下跌趨勢中完全閒置；系統也沒有放空或反向ETF機制。這可能是刻意的保守選擇（只做多、避免額外複雜度與風險），但也代表下跌市場中沒有任何獲利或部分避險手段。

可研究：這是否符合你的風險偏好；若想保留獲利彈性，可評估最小化的避險工具（如反向ETF小倉位）是否值得導入的成本效益。
